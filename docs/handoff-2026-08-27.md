### 1b. A FIXTURE THAT IS NOT THE THING IT CLAIMS

**Three instances, and the third crashed a screen:**

* `conftest._gradient` - the repo's canonical near-duplicate fixture was a **monotonic ramp**
  hashing to `ffffffffffffffff`, the all-one pole. It paired **only because two copies of nothing
  are equal**. The fixture demonstrating the near-dup tier carried no signal for the tier to find.
* `_photo` in `test_the_run_says_what_it_could_not_compare.py` - `Image.new("RGB", (48,48), colour)`,
  a **solid fill**. The file asserting a photograph *"hashed perfectly well"* and was compared used
  a frame with no picture in it.
* `test_ui_regressions.py`'s seed wrote `perceptual="phash-1"` - a string **the product cannot
  produce**. `dedup.pack_hash` parses `perceptual` as base-16 and refuses anything wider than 64
  bits, so `record_uploaded` was the only door wide enough to write it: the fixture went **round**
  the contract rather than through it. When `(ahq)` put a hex parse on the stats path, that one row
  took the whole Stats screen down with a `ValueError`.

**DO:** a fixture that reaches the product through a back door is a fixture nothing validates.
Prefer building test data through the same call the product uses; where that is impractical, make
the value **satisfy the contract anyway** and say in a comment which contract it is. And **no
`try/except` was added** for `phash-1` - swallowing it would be a compat path for data that cannot
exist.

### 1c. A GUARD THAT PINS A DECLARATION, NEVER A BEHAVIOUR

**All three of `PROJECT_STATUS.md` §1b's guards do this**, and it is why condition 1's arithmetic
was wrong in five documents for two days:

* Condition 1's `test_the_app_records_what_a_run_did.py` proves a record entry point is **called**,
  not that a record is **written**. Its table is keyed by service concept while `server.py` is
  keyed by operation string, and **nothing compares the two lists** - so no count derived from
  either could be checked against the other.
* Condition 3's `test_no_thirty_fifth_dead_payload_key.py` says so in its own docstring: *"a
  declaration with a floor, never a proof."*
* Condition 4's guard reads the same declarations condition 1 does.

⚠ **The counter-example shipped today and is the shape to copy.**
`test_a_refused_comparison_is_named.py` registers files into a **real `DedupIndex`**, reads back
what it indexed, and asserts the reported set **equals** the refused set, both directions. A test
that recomputed `carries_no_signal` and compared it with itself would pass forever and prove
nothing.

**DO:** ask of every guard *"what does this fail on?"* If the answer is *"a table nobody updated"*
rather than *"code that does the wrong thing"*, it is a declaration guard - which is legitimate, and
must say so in its docstring the way condition 3's does.

### 1d. A CITATION REPAIRED BY OFFSET

`cli-app-parity.md:161` already rules on this: *"an offset is a guess about a diff, and a citation

**DO:** resolve the **symbol**, never add the diff's offset. `agp.md:56` is the worked example that
did it right, and its commit message says why. `grep -n` on the literal costs seconds.

## 3. WHAT THE BROWSER LANE FOUND THAT `make check` CANNOT

The `(ahq)` batch was green: **3,259 tests passing**, three `check` lanes across Windows, macOS and
Linux. The `workflow_dispatch` browser run on the same tip came back **red**, with two defects
neither reachable nor detectable by any of it:

1. **The Stats screen was crashing on a `ValueError`.** `(ahq)` put a hex parse on the near-dup
   stats path, which had been pure SQL. One unparseable row took the whole screen down. No test
   under `make check` renders a screen, so nothing saw it.
2. **The uncompared block reached no screen at all.** Its payload became a list and the renderer
   was updated; the browser test still posted the old single object. A source check proves the
   payload's *shape*; only a rendered page proves a person can see it.

🔑 **Both were invisible to 3,259 passing tests, and that is the whole argument.** The standing rule
is that the browser lane is a `workflow_dispatch`, not part of the inner loop - correct, because it
costs ~30 minutes. **But fire it on any change that touches `app.js`, before you call the work
done.** The test of *"reaches a screen"* is whether the change could make a screen **stop showing
something**, and a payload changing shape is exactly that.

⚠ **And read a red lane carefully before believing it.** Of the three failures, **one was not
mine**: `renderUnreadable` has four sites, all inside `renderInventoryResult` and
`renderOrganizeResult`, and the archive-ingest renderer holding `rc-cancelled` calls neither. It
also failed on webkit while chromium passed the same test - a code change fails both. It passed on
re-run.

## 6. THE THREE THINGS NOT IN THE DOCS

1. **The push gate refuses on *unknown*, not only on *red*, and the override is yours to run.**
   A tip with no CI run at all - which is what an Actions outage leaves behind - reads as unknown,
   and unknown is not green. `TRUESTILL_PUSH_ANYWAY=1 git push` is the documented answer and it is
   correct to use it **when your own commit is the thing that will establish the answer**: a
   fix-onto-red, or a first push after an outage. Check `gh run list` first and say in the report
   which of the two it was. It was used twice today, for one of each.
2. **`make check` being green is the weakest true statement available about a change that touches a
   screen.** It says nothing rendered wrong because nothing rendered. The corollary nobody writes
   down: the browser lane's ~30 minutes are cheap next to shipping a crashed screen, but only if
   you run the **affected files first** (about two minutes) and the full lane **once**. Iterating
   on the full lane is how 58 of 60 minutes get spent waiting.
3. **The most valuable thing in this repo is the comment two lines above the code you are about to
   change, and it is routinely three months of somebody's evidence.** Every real finding today came
   from reading one: `dedup.py`'s guard naming the failure it could not see; `test_one_identity_in_
   two_places.py`'s diagnosis sitting thirty lines above the test that still had the bug;
   `act.md` saying *"cited by symbol from here on"* six lines above three citations repaired by
   offset. **When a comment and the code beside it disagree, that is the finding** - not a tidying
   job, and not something to fix silently on the way past.
