## 1. THE DAY'S DEFECT CLASSES, AND THE DO FOR EACH

**Five classes, four shipped fixes and two soaks.** The classes are the transferable part; the
letters are instances.

### A. A RECORD WRITTEN BEFORE THE THING IT RECORDS

**Instances**: `(aja)`, `(aiz)`. A `file_copies` row is written when the bytes reach the kernel, so
an interrupted run leaves rows for copies the medium never took - **836 zero-byte files on exFAT
against 2,062 confident rows; 429 backup rows against 124 files on NTFS**. Dedup then read those
rows and the re-run reported *"2,068 already on this drive"*, exit 0, and repaired **nothing**.

🔑 **The row that was wrong defended itself.** That is the class: a claim written early becomes
self-confirming, because the thing that would correct it is the thing that trusts it.

> **DO**: when a record is written before its subject is durable, ask **what re-checks it**. If the
> answer is "the same record", the claim is permanent. **Look, don't remember** - `rsync` stats the
> destination on every run and keeps no record of what it sent; `restic` and `borg` keep the index
> **inside** the repository, and when a client cache diverges the remedy is to delete the cache.

### B. A FIX THAT TURNS A SILENT NO-OP INTO SILENT DUPLICATION

**Instance**: `(aja)`'s second half, and **it was found only because a test failed DIFFERENTLY.**
Once dedup stopped skipping, the repair landed **beside** the corpse as `…_1.jpg`: the drive kept
the ruined file and gained a second one, with the row still pointing at the corpse. The first fix
was correct and made the outcome worse.

> **DO**: when a fix changes a branch, **read the new failure rather than the new pass**. A test
> that goes from "wrong value" to "wrong value for a different reason" is telling you the root is
> deeper. `(ain)`'s self-worsening shape had already been measured once; it arrived again from a
> different side.

### C. A GUARD DEFEATED BY THE SURFACE, NOT BY THE RAISE

**Instance**: `(ajd)`. `_stop_the_run` re-raises on purpose so the run record is written - `(agi)`
working exactly as designed. **The CLI caught only `ValueError`**, so every `OSError` walked past
and reached the user as a **Python traceback with source paths**. `organize` met the identical
accident four hours earlier and answered with a named file, a cause in English,
`2062 organized / 1 failed / 478 not attempted`, and exit 4.

> **DO**: a correct core with no arm to catch it still crashes. When a ruling says *"the surfaces
> handle this"*, **enumerate the surfaces and check each one**. `PROJECT_STATUS.md` §1b's
> condition 2 was ticked ✅ while false for one of them, because the tick was taken per-defect
> rather than per-surface.

### D. FREE EVIDENCE DISCARDED

**Instance**: `(ajb)`. `rescan` walked the drive (stat per file, to know it was a file) and read
the catalog (a size for every copy) - and **compared neither**, reporting 836 zero-byte files as
`in place` in 0.28 s. Its own disclaimer then sent the user away: *"Silent damage changes neither
its name nor its size."*

🔑 **`fsck` on the same volume said *corrupted, 1 file*** - it caught the one genuinely incoherent
entry and was blind to the 836 coherent ones, because a zero-byte file with zero clusters **agrees
with itself**. Only the catalog, which lives outside the filesystem, knows the difference.

> **DO**: before adding an instrument, ask what the existing one **already has in hand**. And when
> a disclaimer tells the user a check would not help, **that sentence is part of the defect**.

### E. A FIX THAT QUIETLY NARROWS WHAT CALLERS MAY CATCH

**Instance**: `BackupStoppedError`, first written as an `Exception` subclass. **Eleven passing app
tests refused it** - it broke every `except OSError`, which is the contract `_copy_missing`
documents as *"re-raised UNCHANGED"*. Making it an `OSError` subclass keeps every existing catcher
and the `errno` while **adding** the counts.

> **DO**: widening what an error carries is safe; **changing what it IS is a second defect**. Ask
> what already catches this before choosing a base class.

## 3. WHAT THE SOAKS ESTABLISHED

**Three filesystems, three physical mid-write pulls, on one USB stick.**
[`soak-ten-record.md`](soak-ten-record.md) is the quiesced pull;
[`soak-eleven-record.md`](soak-eleven-record.md) is the interrupted one.

🔑 **THE SENTENCE THAT CARRIES IT: a missing file is honest; a zero-byte file is a lie.**

| | exFAT | NTFS | FAT32 |
|---|---|---|---|
| zero-length after the pull | **836** | 0 | **38** |
| unreadable / missing | 2 | **304 unreadable** | 1 |
| size-correct, bytes wrong | 1 | 1 | 0 |
| the volume afterwards | remounted `rw`, silently | ⚠ **refused to mount** | `rw`, with a warning |
| dirty in RAM at the pull | 3.5 GB | 2.7 GB | **16 MB** (`flush` mount option) |

**The damage SHAPE is set by the filesystem; the window SIZE by the mount options.** FAT32 - the
weakest - lost the least, purely because udisks2 mounts vfat with `flush`.

**`verify` caught every damaged file on all three**: 839, 305, 39, checked by set intersection of
paths rather than by count. **`rescan` caught 2, then 304, then 1** - high only where the journal
made absence honest, which is why `(ajb)` is scoped to filesystems that keep the directory entry.

## 5. WHAT IS UNFINISHED, AND WHY

- **`(ajf)` - should a command say *"copied"* before the medium has the bytes?** ⚠ **A product
  ruling, deliberately not made in a defect fix.** `safe_copy` refuses `fsync` in its own words and
  nominates `copy_sha256` and `verify` to own durability. The field settled the same argument for
  `rsync` with `sync()` before exit - Ts'o, *"not a big deal, and not all that costly"* - and
  **fsyncgate is why that makes the TIMING honest without making the outcome certain**.
- **Soak twelve's app half.** The damaged-decisions-document case ran and produced `(aje)` in sixty
  seconds; **the app half never started.** It needs the browser lane and a loop device, both
  approved, neither used.
- **What today's fixes left standing.** Size is not content: a copy whose size matches and whose
  bytes are wrong survives every fix here - one measured on each of exFAT and NTFS - and only
  `verify` finds it. `(ajd)` gave the **CLI** an arm and left `service/backup.py` alone.
  `(ajb)`'s `damaged` bucket has **no repair**, which is `(abn)`.
