## 6. Three things an arriving engineer needs that are not in the docs

1. **The push lane has zero browser coverage, and "green" hides that.** The e2e job is gated to
   `schedule` and `workflow_dispatch`; a push run lists it as *skipped*, which reads as green in
   every summary. After a change that reaches a screen, dispatch the lane and wait for it. The
   nightly is a request, not a promise - it fired at 08:04 UTC for a 03:17 cron this week.
2. **Three tooling traps cost real time this session, each once-per-session at most.** An edit
   script whose anchor ruff has reflowed asserts and writes nothing, silently - anchor on a span
   or check the file changed. `pkill -f <pattern>` kills your own shell when the pattern is in your
   command line - use `pkill -x`. And pwsh neither waits for a GUI-subsystem program nor sets
   `$LASTEXITCODE` for it: `Start-Process -Wait -PassThru` and `.ExitCode`, which the release lane
   now does and its guard pins.
3. **A checkout without Node is honestly incomplete, and the self-check says so.** `make check` is
   green with no Node by promise, so on the CI check lanes `truestill-app --self-check` exits 1
   naming the unbuilt bundle. That is the truth, not a failure to route around: the flag tests
   accept exactly that incompleteness and no other. Build the bundle (`make frontend-install &&
   make frontend`) before you run the app from a clone.
