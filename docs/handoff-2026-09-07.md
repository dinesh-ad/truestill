## 4. What is open, and why it matters

**From the rebuild, and each of these is mine:**

- **The stepper says "Preview" while the typed confirm is on screen.** The state at that moment is
  `preview` (`app.js:2605`), and `main.tsx:stepFor` maps it to step 2. The mapping is one-to-one on
  the kinds as briefed and internally consistent; it does not describe where the person is.
- **The action bar's size figure is the source's, not the run's.** `ActionSummary`
  (`main.tsx:434`) takes the file count from `will_organize` once a preview exists but the bytes
  from `foundInFolder`, which is the inventory's total. On a run with duplicates those are two
  different denominators in one sentence, six pixels apart. The fix is either to drop the size or
  to have the preview carry the bytes it will write; the field does not exist today.
- **The counts vanish at `running` and `complete`.** `foundInFolder` (`main.tsx:365`) returns
  `null` for both, so the figures beside the folder field disappear at the moment the run starts.
  Defensible - the result region owns the finished numbers - but it reads as a glitch.
- **The mode cards collapse at a VIEWPORT threshold** (`app.css`, `@media (max-width: 1023px)`)
  standing in for a content-column one. The real quantity is the column width after the rail and
  the padding; a container query expresses that and a media query does not.
- **The plate is 36 px in a 232 px rail.** Measured collapsed: the rail is 64.00 px, the plate
  32.72 × 36.00, leaving 15.14 px left and 16.14 px right, no overflow. **Whether it reads as a
  mark at that size is unestablished** - it is a judgement, and nothing here measured it.
- **The screen now asks HOW before it asks WHERE.** The first-run question is at
  `index.html:250`, below the mode cards at `:202`. Folding it into the card was the instruction
  and it is right; its position is a consequence nobody chose. Putting it inside `#org-dest-field`
  was rejected because `renderOrganizeMode` (`app.js:2103`) hides that field in inplace mode, so a
  first-run user picking "Reorganize in place" would never be asked at all.

**Two silently-dead assertions this rebuild uncovered. Same class, and both invisible until
something moved:**

- `test_rail_shell.py::test_the_rail_mark_paints_when_the_rail_is_collapsed` asserted the first
  `<path>`'s fill was "not `none` and not transparent". In the plate those paths are inside a
  `<mask>` at `fill: #000` and paint nothing - and `#000` satisfies that assertion. It would have
  gone on passing forever against an element that is never drawn.
- `test_rail_shell.py::test_the_rail_artwork_matches_the_authored_source` compared the inlined
  paths to `brand/pillar-t-geometric-noflute.svg`, a file the screen no longer uses. The plate
  carries byte-identical paths, so it kept passing while pointing at the wrong source; an edit to
  the plate would not have been caught.

**The class is a test whose subject moved out from under it while its assertion stayed true.** No
guard is possible - a guard would have to know what a test meant. Both were found by changing the
thing they watch, which is the only way this class is ever found, and it is worth assuming there
are more.
