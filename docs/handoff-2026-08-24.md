## Three things you need that are not in the docs

1. **The push flow has two escapes and you may run one of them.** Fix-onto-red:
   `TRUESTILL_PUSH_ANYWAY=1 git push`, yourself, no asking (ruled 2026-08-24; memory +
   `.pre-commit-config.yaml` carry it). It waives the OUTCOME only; contention WAITS 480 s then
   refuses, and killing a live run is `TRUESTILL_PUSH_CANCELS_THE_RUN=1` - a separate decision.
   The audit lines print even on green (`verbose: true`).
2. **A dirty tree may not be yours.** Peer sessions work this repo in parallel; twice this
   session another session's uncommitted work sat in the tree (once red). Before gating or
   committing, `git status` and attribute every entry; gate your own change in a throwaway
   worktree (`git worktree add <path> origin/main`, copy your files, `git add` new files BEFORE
   `make check` - tracked-source guards read `git ls-files`). Never stash or discard what you
   did not write.
3. **The three `check` lanes are the review.** Four cross-platform defects were caught by them
   in one day (BSD `df`, GNU `--output`, depth-1 checkout shas, a stripped `SYSTEMROOT`) - every
   one a check that was true locally and false where it ran. Assume your harness has one of
   these until macOS and Windows have said otherwise, and never hand-roll a subprocess
   environment or format outside `make format` (the `--target-version py313` pin is what keeps
   PEP 758 out).
